# Failure normalization boundary (Team 2, R2-08, runtime side)

Vendor-to-class wire mapping is JOINT with Team 3 (they own parsing; this doc owns the boundary signals). Live-shape proof is T3 P3-04 + T4-LIVE-PAYLOAD.

## Runtime-side classes (what the loop actually observes)

| Malfunction                    | Signal seen by the loop                                                             | Normalized to                                                                                                                                                                                              | Retryable                                  |
| ------------------------------ | ----------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------ |
| Malformed provider event       | `AsyncQueue.fail(throwable)` / iterator throw                                       | `stt.failed` / `llm.failed` / stage error, provider preserved                                                                                                                                              | per wrapped error                          |
| Remote close / network failure | socket `close` -> queue `fail` (`unexpectedEof`/`protocolError`) / `connect_failed` | `stt.failed` (+ `call_ended{failed}`)                                                                                                                                                                      | `unexpectedEof`/`service_unavailable` only |
| Timeout                        | `stallTimer` fire / `withTimeout` / commit timer                                    | `llm.stalled` / `tts.stalled` / `stt.commit_timeout` / `stt.open_timeout` (`TimeoutError`, retriable), except `stt.drain_timeout`, which is non-retriable post-shutdown housekeeping (`recoverable:false`) | per row                                    |
| Cancellation                   | `AbortSignal` / iterator break / transport end                                      | `cancelled` family (`call.cancelled`, `stt.open_cancelled`, `tool.cancelled`)                                                                                                                              | false                                      |
| Unsupported capability         | `defineAgent` compat check at construction                                          | `agent.provider_incompatible` (`ValidationError`)                                                                                                                                                          | false                                      |

## Boundary rules (LOCKED)

- Awaiters reject with the same normalized value the iterator yields as `error` (deep-equal `{name,code,category,message,retriable,provider}`). Stage travels through the provider name and dotted code prefix because `NormalizedError` has no separate stage field. No raw error leaks across this boundary.
- Errors are JSON-safe within budgets: `maxErrorCauseBytes=4k` (oversized `cause` -> `{ $tvic: cause_truncated, bytes, preview }`), `maxToolInputBytes=64k` (oversized `tool_call.input` -> `{ $tvic: input_truncated, bytes }`). Unserializable causes -> `{ $tvic: cause_unserializable }`.
- Redaction scope: schema-invalid or unserializable tool input is emitted and persisted as `input_unavailable`. Valid input is emitted and persisted verbatim. Application-level secret policy owns PII and secret redaction.
- `stt.command_failed` is the fallback code when the failure value is neither normalized nor marked; in practice the command controller pre-wraps failures, so normalized codes/retriability pass through untouched and raw transport errors surface as `internal` with the message preserved (retry decisions for future STT generations live in the resilient-STT policy mapping). `tool.not_found` is a `ValidationError` (model hallucination), never `internal`.
