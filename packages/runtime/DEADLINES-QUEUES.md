# Deadlines and bounded queues (Team 2, R2-05)

## Per-stage deadlines

| Stage                              | Deadline                                                                | Timeout code                                    | On fire                                                                | Configurable                                |
| ---------------------------------- | ----------------------------------------------------------------------- | ----------------------------------------------- | ---------------------------------------------------------------------- | ------------------------------------------- |
| STT open                           | 15s `STARTUP_TIMEOUT_MS`                                                | `stt.open_timeout`                              | fail startup (typed, late stream closed)                               | no                                          |
| STT commit (provider mode)         | 5s `commitTimeoutMs`                                                    | `stt.commit_timeout` (`TimeoutError`)           | fail barrier + terminal stream failure                                 | via `SttCommandController` / reconnect opts |
| STT commit (`commitMode:none`)     | none; barrier resolves locally, no provider round-trip                  | n/a                                             | n/a                                                                    | n/a                                         |
| Reconnectable STT graceful drain   | 5s `CANCELLATION_TIMEOUT_MS`                                            | `stt.close_timeout`                             | fail close and controller; close provider best-effort                  | no                                          |
| LLM / TTS startup                  | 15s `STARTUP_TIMEOUT_MS`                                                | `llm.open_timeout` / `tts.open_timeout`         | fail startup (typed, late handle cancelled)                            | no                                          |
| Endpoint debounce                  | 3s `DEFAULT_TURN_ENDPOINT_TIMEOUT_MS`                                   | synthetic endpoint commit                       | commits buffered finals as a turn                                      | `turnEndpointTimeoutMs`                     |
| Utterance cap                      | 30s `DEFAULT_TURN_MAX_DURATION_MS`                                      | synthetic endpoint commit                       | commits buffered finals as a turn                                      | `turnMaxDurationMs`                         |
| Commit-finalize grace              | 250ms `TRANSCRIPT_FINALIZE_GRACE_MS`                                    | n/a                                             | proceeds with buffered finals                                          | no                                          |
| LLM / TTS stall                    | shared `#stallTimeoutMs` (default `agent.timeoutPolicy.timeoutMs`, 10s) | `llm.stalled` / `tts.stalled` (`TimeoutError`)  | `onTimeout: fail` -> fail turn; `interrupt` -> cancel turn (`timeout`) | `streamStallTimeoutMs`, `timeoutPolicy`     |
| LLM / TTS iterator cleanup         | 5s `CANCELLATION_TIMEOUT_MS`                                            | `voice_runtime.cancellation_timeout`            | continue teardown and report degraded cleanup                          | no                                          |
| Persona resolve / per-turn prompt  | 1s each, SWALLOWED (no error code)                                      | n/a                                             | falls back to base/session prompt                                      | no (known outlier, documented)              |
| Playout confirm                    | 30s `PLAYOUT_CONFIRM_TIMEOUT_MS`                                        | unconfirmed (`false`)                           | turn `cancelled(not_heard)` unless text delivered                      | no                                          |
| `callHandle.clear()`               | 250ms `CLEAR_TIMEOUT_MS`                                                | swallowed                                       | continues teardown                                                     | no                                          |
| Transcript drain (post-shutdown)   | 5s `TRANSCRIPT_DRAIN_TIMEOUT_MS`                                        | `stt.drain_timeout`                             | ends session without stragglers; late transcripts dropped by gate      | no                                          |
| Durable write                      | 75ms `criticalWriteTimeoutMs`                                           | `BackendUnavailableError`                       | caller fails bounded; late commit reconciled                           | `durablePolicy`                             |
| Turn-terminal read grace           | 2s `persistenceRecoveryGraceMs`                                         | n/a                                             | `awaitTerminalTurn` polling                                            | `durablePolicy`                             |
| Session memory finalize / end hook | 1s / 5s                                                                 | `timed_out(drain\|purge)` / hook timeout metric | release caller, preserve ordering                                      | `RuntimeOptions`                            |

Known outlier (documented, not changed in 1.1.0): Terminate-style graceful closes (about 2s for AssemblyAI and Soniox) exceed CLEAR 250ms. The pipeline preempts at 250ms, so CLEAR wins and Terminate is dropped and counted.

## Timer and listener lifecycle notes

- Caller-visible deadline timers stay referenced so a bare Node process cannot exit before a timeout is reported. Background housekeeping timers such as provider keepalives and recovery polling may be unref'd where they do not carry the only correctness signal.
- `abortPromise` listeners are per-turn and collected with their `AbortController`; `withTimeout` removes its listener on settle. `stt-session.ts` uses the single `async-control.ts` copy (the `internal/async.ts` duplicate remains for compatibility).
- `commitMode:none` providers resolve commit barriers locally with no provider round-trip and no commit timeout; ordering is still serialized through the command worker.

## Straggler bound note

Graceful-shutdown straggler turns (buffered finals flushed after the commit
barrier) run full `#handleTranscript` work, but every stage inside is itself
deadline-bounded (LLM/TTS stall 10s default, tool timeouts per definition,
playout confirm 30s worst case). Settlement therefore waits at most the
configured stall budgets, never indefinitely; the transcript drain deadline
(5s) bounds the provider side independently.
