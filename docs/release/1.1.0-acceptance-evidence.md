# 1.1.0 acceptance evidence

Status: in progress

This is the tracked release evidence index for the 1.1.0 quality, security, and
release work. It is deliberately independent of `local/`, because a clean
checkout used by CI and release automation cannot read ignored planning files.

The starting state is recorded in
[`1.1.0-baseline.md`](./1.1.0-baseline.md).

The rows below describe the acceptance contract. A row is not complete merely
because its command exists. The release record must contain the exact commit,
workflow run, artifact digest, result, and limitation after the command runs.

## Acceptance matrix

| ID    | Requirement                 | Required result                                                                                                                     |
| ----- | --------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| Q4-01 | Verification gate matrix    | Every event has an explicit owner, job, command, and failure boundary.                                                              |
| Q4-02 | Aggregate `Verify` contract | The required aggregate check reflects every required dependency and never passes a failed or cancelled dependency.                  |
| Q4-03 | Deterministic harness       | Security rejection and lifecycle tests prove that rejected input creates no downstream side effect.                                 |
| Q4-04 | Flake audit                 | Timing-sensitive tests use controlled synchronization and have repeatable results.                                                  |
| Q4-05 | External package proof      | The exact packed artifact works from a clean consumer project with ESM, CommonJS, TypeScript, and intended files.                   |
| Q4-06 | Threat model                | Security assets, attackers, mitigations, tests, owners, and residual risks are documented.                                          |
| Q4-07 | Fail-closed security        | Invalid authentication, replay, malformed input, missing production configuration, and secret leakage are rejected or absent.       |
| Q4-08 | Release workflow            | The release workflow verifies the protected source commit, required gates, trusted publisher, and exact artifact before publishing. |
| Q4-09 | Release record and recovery | A release can be audited and recovered without an Action mutating the repository.                                                   |
| Q4-10 | Support claims              | Node, provider, transport, and stability claims match executable checks and documentation.                                          |
| Q4-11 | Failure diagnostics         | Required failures identify the stage and preserve safe, actionable diagnostics.                                                     |
| Q4-12 | CI cost                     | Static checks run once, event-specific checks are scoped, and skipped jobs are interpreted explicitly.                              |
