# 1.1.0 CI gate matrix

The single required branch-protection check is the displayed check named
`Verify`. Event-specific jobs are dependencies of that aggregate and are not
required directly by branch protection.

| Requirement                                  | Event                                                         | Job                                                  | Command or decision                                                  | Owner         | Failure caught                                                       |
| -------------------------------------------- | ------------------------------------------------------------- | ---------------------------------------------------- | -------------------------------------------------------------------- | ------------- | -------------------------------------------------------------------- |
| Formatting, types, architecture, inventories | Pull request, merge group, main push, manual                  | `lint`                                               | `pnpm lint`, `pnpm check:ci-routing`, and `pnpm check:ci-gates`      | Team 4        | Invalid source or repository contract                                |
| Fail-closed security                         | Pull request, merge group, main push, manual                  | `security`                                           | `pnpm check:security`, build, provider and ingress security tests    | Team 4        | Public bypass, authentication, replay, or secret-boundary regression |
| Deterministic package and runtime behavior   | Pull request and merge group                                  | `pr_verify`                                          | Build, `pnpm test`, exports, external package check                  | Teams 1 to 4  | Review-visible runtime or package regression                         |
| PostgreSQL and Redis behavior                | Pull request and merge group when `change_scope` says durable | `pr_durable`                                         | Service-backed durable adapter tests and public durable check        | Teams 2 and 4 | Persistence, migration, lease, or serialization regression           |
| Supported Node runtime behavior              | Main push                                                     | `main_runtime`                                       | Runtime test matrix on Node 22, 24, and 26                           | Team 4        | Runtime compatibility breakage                                       |
| Main package boundary                        | Main push                                                     | `main_artifact`                                      | Build, exports, and external package check                           | Team 4        | Main artifact or export mismatch                                     |
| Main durable behavior                        | Main push                                                     | `main_durable`                                       | Service-backed migrations and durable checks                         | Teams 2 and 4 | Main persistence regression                                          |
| Manual full verification                     | Manual dispatch                                               | `manual_verify`                                      | Full static, package, runtime, migration, and durable checks         | Maintainer    | Deliberately requested broad verification failure                    |
| Durable result interpretation                | Every event                                                   | `durable_gate`                                       | Converts applicable durable result to required or not applicable     | Team 4        | A skipped or cancelled durable job being treated as a pass           |
| Required aggregate                           | Every event                                                   | `Verify`                                             | Asserts lint, security, durable gate, and event-specific job results | Team 4        | Required checks disappearing or passing after dependency failure     |
| Release source and package                   | Release published                                             | `release_lint`, `package_artifact`, `release_verify` | Exact-tag static checks, SHA proof, one packed artifact, full tests  | Team 4        | Unreviewed source, bad package, or untested bytes                    |
| Release publication                          | Release published                                             | `publish`                                            | Download, hash-check, and publish the tested tarball                 | Maintainer    | Artifact substitution or unauthorized npm publication                |

Credentialed provider smoke tests remain outside the release gate. They are
manual evidence for the selected provider, model, voice, transport, and commit,
not a prerequisite for publishing the npm artifact.

## Compute policy

- Static lint and inventory checks run once per event, outside the Node matrix.
- Pull requests run the full deterministic package/runtime suite once on Node 24.
- Main runs the runtime suite on Node 22, 24, and 26 because that is the claimed
  compatibility surface, while artifact and durable checks each run once.
- Durable services are provisioned only when a path can affect persistence, plus
  the explicit main and release gates.
- The release builds one tarball. Consumer compatibility jobs test that same
  tarball rather than rebuilding it.
- A cancelled dependency cannot make `Verify` pass. A job skipped because it is
  inapplicable is accepted only through the event-specific truth table in the
  aggregate job.
