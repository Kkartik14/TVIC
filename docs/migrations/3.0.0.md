# Upgrade to `voice-runtime` 3.0.0

Version 3.0.0 adds provider-aware speech controls and capability preflight. It
also tightens several TTS validation rules and adds compatibility issue codes.
Review the changes below before upgrading from 2.1.0 or an unreleased 2.2.0
checkout.

## TTS failover metadata

Failover copies request metadata before calling the primary, so metadata must be
structured-cloneable on every request. Class instances become plain objects;
methods and custom prototypes are not retained. Use plain records, arrays, and
primitive values for metadata. The failover mapper may return a fresh object, but
it must preserve session and turn IDs, text, format, timing options, controls,
metadata, usage reporting, and the caller's `signal`. Validation errors list
protected fields that were changed or dropped. Provider and cancellation errors
keep their code, retryability, and existing cause. Non-cancellation errors
returned from an attempted fallback include `metadata.primaryProvider` and
`metadata.primaryCode`; a primary provider error that does not trigger fallback
is propagated unchanged and may not carry that metadata. A mapped-request
validation error uses the primary failure as its cause only when the mapper's
error has no cause of its own.

When `fallbackVoiceMappings` is configured, every requested model and voice
that may reach the primary must have a matching table entry. A custom
`mapFallbackRequest` can still compute the mapped request, and its model and
voice must match the table. Mapper-only selection keeps the primary model and
voice catalog and can map requests dynamically. If the fallback uses
account-backed voices and capability snapshots are enforced, declare the table
so startup can validate mapped voices before a call. Without snapshots, mapper-
only setups remain available.

For dialogue adapters behind failover, map every registered primary dialogue
voice and map only to voices registered by the fallback dialogue adapter. The
snapshot loader receives provider/model/voice selections for both children and
for each declared mapping. Startup checks both sides even when both children
use the same vendor account.

Failover now reports the primary provider's model and voice catalogs when a
request mapper owns selection. Text controls are checked against the primary
before synthesis and against the fallback only if failover is attempted. This
differs from speed preflight when no request mapper is configured: speed is
checked against both children before primary synthesis, while unsupported
fallback text controls can prevent fallback only after the primary fails.

## Cartesia settings

- Speed must be between `0.6` and `1.5`, inclusive.
- Normalization and pronunciation dictionary IDs are accepted only for models
  where the catalog declares support, currently Sonic 3.6 models.
- Explicit languages are checked against the chosen model when a language map is
  published. For catalog models without a map, valid language tags pass through
  to Cartesia without local language support validation.
- `finish()` rethrows a provider failure already received by the stream. Catch
  failures from `finish()` and stop using that stream.

Cartesia passes provider markup embedded in transcript text through by default,
preserving 2.1 behavior for hosts whose generated transcript intentionally uses
Cartesia tags such as `<emotion>` or `[laughter]`. A live call confirmed that
`<spell>...</spell>` is interpreted as an instruction and entity escapes are
spoken as their entity names. Set `transcriptMarkup: "reject"` to reject
supported provider markup in source text. Typed `textControls` remain available
for spelling and pauses. TVIC leaves source ampersands and angle characters
unchanged in either mode.

## ElevenLabs settings

The adapter rejects `language` for Text-to-Dialogue models and for
`eleven_multilingual_v2`, where the configured `language_code` option is not
supported by this API route. Omit the language or choose a model and route that
accepts it.

Voice categories in capability snapshots now include `famous` and
`high_quality`. Null locale entries no longer erase other valid verified
locales for the same voice and model. A model-specific voice check now requires
a fact for that model. Hand-built snapshots that only record a model-independent
voice fact must add a model-scoped availability fact for each selected model.
The ElevenLabs loader now emits those facts for requested model IDs.

HTTP Text-to-Dialogue defaults to `eleven_v3` when the configured speech model
is not a dialogue model. Explicit dialogue models must start with `eleven_v3`.
For a managed WebSocket dialogue agent, every `dialogueVoices` entry is checked
before call startup and is included in the snapshot loader context.

## TTS failover speed

When speed is configured, both children must declare a compatible speed range.
Remove speed or choose providers with overlapping declared ranges if failover
construction rejects the configuration.

## Sarvam Bulbul v4 Flash temperature

An explicit `temperature` now fails validation on WebSocket, REST, and
HTTP-stream routes for `bulbul:v4-flash`; it is not sent to Sarvam. The REST and
HTTP-stream behavior is newly stricter. Remove `temperature` when selecting v4
or keep it with v3. The [v4 best-practices guide](https://docs.sarvam.ai/api/api-guides-tutorials/text-to-speech/best-practices)
says temperature is silently ignored. The [WebSocket reference](https://docs.sarvam.ai/api-reference/text-to-speech/stream)
and [REST reference](https://docs.sarvam.ai/api-reference/text-to-speech/convert)
list v4 Flash as supported, while the [HTTP-stream guide](https://docs.sarvam.ai/api/api-guides-tutorials/text-to-speech/streaming-api/http-stream)
limits temperature to v3. A live WebSocket request was accepted and returned
audio, which confirms acceptance only, not an effect on prosody. TVIC follows
the model-specific guide and rejects the option so a host cannot mistake
acceptance for tuning.

Sarvam's v4 best-practices guide lists pitch and loudness as accepted, while the
REST and WebSocket references say they are unsupported for v4 Flash. TVIC leaves
those options unchanged until the vendor documentation or a live check resolves
the conflict.

## Snapshot loader and call-start deadlines

`loadProviderCapabilitySnapshots` must return an array. Its deadline is now
separate from `startupTimeoutMs`: snapshot loading defaults to 30 seconds, and
ordinary startup and the call-handle factory keep the 10-second default.
`providerCapabilitySnapshotTimeoutMs` can shorten or extend only the loader
budget. The loader selection now includes
`providerCapabilitySnapshotProviders`,
`providerCapabilitySnapshotSelections`, and
`providerCapabilitySnapshotVoices` as provider/model/voice selections;
selections may identify request-selected versus mapping-selected models with
`modelSource`. Callbacks may use these fields to fetch all snapshots the
selected adapter needs. The bundled Cartesia loader returns one
snapshot, so wrap it in an array from the callback. Snapshot-load timeouts
retain `voice_runtime.start_timeout` and carry
`metadata.timeoutScope: "provider_capability_snapshot_loader"` with a
loader-specific message.

## Provider compatibility issue codes

`ProviderCompatibilityIssueCode` now includes:

- `turn_profile.unsupported`
- `tts_text_control.unsupported`
- `tts_speed.unsupported`

Update exhaustive switches over compatibility issue codes to handle these
values.
