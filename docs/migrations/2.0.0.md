# Upgrade to `voice-runtime` 2.0.0

`2.0.0` is a major release because the public durable-store contracts change in
source-incompatible ways. Custom `SessionLeaseStore` and
`ToolIdempotencyStore` implementations built against `1.2.0` must be updated
before they compile against `2.0.0`.

This guide covers the adapter changes and the PostgreSQL rollout. The regular
runtime, transport, provider, and observability APIs are summarized in the
[2.0.0 changelog](../../CHANGELOG.md#200) and the relevant guides.

## Before upgrading

1. Inventory every process that can write sessions, turns, tool calls, leases,
   or idempotency records. Include recovery workers, reapers, background jobs,
   and applications that call the stores directly.
2. Update custom adapters to the contracts below and exercise them against the
   same PostgreSQL or Redis backend used in production.
3. Confirm that tool executors pass the stable idempotency key to providers
   that support duplicate protection. Identify how operators will reconcile an
   external action whose outcome is ambiguous.
4. Back up the durable database and schedule the writer drain described below.

Do not run 1.2.0 writers alongside 2.0.0 writers while changing the idempotency
key format. The legacy lookup cannot arbitrate simultaneous old and new claims.

## `SessionLeaseStore` changes

In 1.2.0, a lease was identified by session, holder, and numeric fence. Recovery
returned session IDs, with no explicit acknowledgment method:

```ts
interface SessionLease {
  sessionId: SessionId;
  holder: string;
  fence: number;
  acquiredAtMs: number;
  renewedAtMs: number;
  expiresAtMs: number;
}

interface SessionLeaseStore {
  acquire(sessionId: SessionId, holder: string, ttlMs: number): Promise<SessionLease | null>;
  renew(
    sessionId: SessionId,
    holder: string,
    fence: number,
    ttlMs: number,
  ): Promise<SessionLease | null>;
  release(sessionId: SessionId, holder: string, fence: number): Promise<void>;
  listRecoveryCandidates(options: {
    nowMs: number;
    limit: number;
    cursor?: string;
  }): Promise<{ sessionIds: readonly SessionId[]; nextCursor?: string }>;
  get(sessionId: SessionId): Promise<SessionLease | null>;
  close(): Promise<void>;
}
```

In 2.0.0, the generation ID is part of lease ownership. Keep it stable for one
acquisition, issue a new one for every later acquisition, and validate it with
the holder and fence on every fenced operation. Recovery returns exact expired
generations and requires acknowledgment after handling each candidate:

```ts
interface SessionLease {
  sessionId: SessionId;
  holder: string;
  fence: number;
  generationId: string;
  acquiredAtMs: number;
  renewedAtMs: number;
  expiresAtMs: number;
}

interface SessionRecoveryCandidate {
  sessionId: SessionId;
  fence: number;
  generationId: string;
}

interface SessionLeaseStore {
  acquire(sessionId: SessionId, holder: string, ttlMs: number): Promise<SessionLease | null>;
  renew(
    sessionId: SessionId,
    holder: string,
    fence: number,
    ttlMs: number,
    generationId: string,
  ): Promise<SessionLease | null>;
  release(sessionId: SessionId, holder: string, fence: number, generationId: string): Promise<void>;
  listRecoveryCandidates(options: { nowMs: number; limit: number; cursor?: string }): Promise<{
    candidates: readonly SessionRecoveryCandidate[];
    corruptLeaseSessionIds?: readonly SessionId[];
    nextCursor?: string;
  }>;
  acknowledgeRecoveryCandidate(candidate: SessionRecoveryCandidate): Promise<void>;
  get(sessionId: SessionId): Promise<SessionLease | null>;
  close(): Promise<void>;
}
```

The cursor is opaque. Pass `nextCursor` through even when a page has no
candidates. Acknowledgment must be atomic for the exact expired generation and
must not delete session data or acknowledge a generation that is active or has
been replaced. A stale worker must fail lease validation even if its holder or
numeric fence is reused.

## `ToolIdempotencyStore` changes

The 1.2.0 store already had `lookup()`, `claim()`, and `complete()`. In 2.0.0,
lookup is session- and lease-aware, claim results distinguish terminal outcomes,
and the store adds an atomic claim release and an atomic quarantine operation.

```ts
// 1.2.0
interface ToolIdempotencyLease {
  sessionId: SessionId;
  holder: string;
  fence: number;
}

interface ToolIdempotencyClaim {
  key: string;
  lease?: ToolIdempotencyLease;
  toolId?: ToolId;
  toolVersion?: string;
  requestHash: string;
  owner: string;
  ttlMs: number;
}

type ToolIdempotencyClaimResult =
  | { status: "claimed"; record: ToolIdempotencyRecord }
  | { status: "succeeded"; record: ToolIdempotencyRecord }
  | { status: "in_progress"; record: ToolIdempotencyRecord }
  | { status: "conflict"; record: ToolIdempotencyRecord };

interface ToolIdempotencyStore {
  lookup(key: string, requestHash: string): Promise<ToolIdempotencyRecord | null>;
  claim(input: ToolIdempotencyClaim): Promise<ToolIdempotencyClaimResult>;
  complete(key: string, requestHash: string, outcome: ToolIdempotencyOutcome): Promise<void>;
}

// 2.0.0
interface ToolIdempotencyLease {
  sessionId: SessionId;
  holder: string;
  fence: number;
  generationId: string;
}

interface ToolIdempotencyClaim {
  key: string;
  sessionId?: SessionId;
  lease?: ToolIdempotencyLease;
  toolId?: ToolId;
  toolVersion?: string;
  requestHash: string;
  owner: string;
  ttlMs: number;
}

type ToolIdempotencyClaimResult =
  | { status: "claimed"; record: ToolIdempotencyRecord }
  | { status: "succeeded"; record: ToolIdempotencyRecord }
  | { status: "terminal"; record: ToolIdempotencyRecord }
  | { status: "in_progress"; record: ToolIdempotencyRecord }
  | { status: "conflict" };

interface ToolIdempotencyStore {
  lookup(
    key: string,
    requestHash: string,
    sessionId?: SessionId,
    lease?: ToolIdempotencyLease,
  ): Promise<ToolIdempotencyLookupResult>;
  claim(input: ToolIdempotencyClaim): Promise<ToolIdempotencyClaimResult>;
  releaseClaim(input: ToolIdempotencyRelease): Promise<boolean>;
  complete(key: string, requestHash: string, outcome: ToolIdempotencyOutcome): Promise<void>;
  quarantine(input: ToolIdempotencyQuarantine): Promise<ToolIdempotencyQuarantineResult>;
}

interface ToolIdempotencyRelease {
  key: string;
  requestHash: string;
  owner: string;
  sessionId?: SessionId;
  lease?: ToolIdempotencyLease;
}

interface ToolIdempotencyQuarantine {
  key: string;
  sessionId: SessionId;
  lease: ToolIdempotencyLease;
  toolId: ToolId;
  toolVersion: string;
  requestHash: string;
  owner: string;
  ttlMs: number;
  error: NormalizedError;
}

type ToolIdempotencyLookupResult =
  | { status: "found"; record: ToolIdempotencyRecord }
  | { status: "missing" }
  | { status: "conflict" };

type ToolIdempotencyQuarantineResult =
  | { status: "quarantined"; record: ToolIdempotencyRecord }
  | { status: "succeeded"; record: ToolIdempotencyRecord }
  | { status: "terminal"; record: ToolIdempotencyRecord }
  | { status: "in_progress"; record: ToolIdempotencyRecord }
  | { status: "conflict" };
```

The method signatures alone do not describe the full contract. Update the
associated input and result types as well:

- `ToolIdempotencyLookupResult` is `found` with a record, `missing`, or
  `conflict`. A conflict must not disclose another request's record or payload.
- `ToolIdempotencyClaim` can carry the session ID and current lease. Its lease
  now includes `generationId`; validate that ID with the holder and fence. The
  old `conflict` claim result included a record; 2.0.0 removes it to avoid
  disclosing a different request's data.
- A matching successful claim returns `succeeded`; failed, timed-out,
  cancelled, and quarantined records return `terminal`. Do not replace terminal
  results with a new claim.
- `releaseClaim()` removes only the matching active claim (key, request hash,
  owner, and supplied lease). It returns `false` when no matching active claim
  can be removed and rejects with `LeaseLostError` for a stale supplied lease.
- `complete()` keeps its method signature, but its outcome may include the
  session and current lease. Session-scoped completion must be fenced by that
  lease.
- `quarantine()` validates the current session lease and atomically records an
  ambiguous recovered attempt as terminal. Its result preserves an existing
  outcome when another owner already completed the operation.

When a worker crashes after an external side effect may have happened but
before its result is durable, recovery uses `recoveryPolicy: "do_not_replay"`.
Reconcile the provider or business operation before starting a new action.
Unclassified tool exceptions are also non-retriable by default in 2.0.0; throw
an explicit TVIC error with `retriable: true` only when retrying is safe.

## PostgreSQL migration order and writer drains

`runPostgresMigrations()` loads the bundled SQL, takes the migration advisory
lock, sorts pending migrations by numeric version, and records each applied
version in `tvic_schema_migrations`. Run the normal migration runner once for
the deployment; do not manually reorder or renumber the files.

The PostgreSQL migration files in this release are:

| Version | File stem                                    | Purpose                                                                         |
| ------- | -------------------------------------------- | ------------------------------------------------------------------------------- |
| 005     | `lease_generation_identity`                  | Adds the lease generation identity.                                             |
| 006     | `lease_generation_backfill_index`            | Supports generation backfill and lookup.                                        |
| 007     | `recovery_candidate_index_concurrently`      | Adds the recovery-candidate index.                                              |
| 008     | `drop_unfiltered_lease_expiry_index`         | Removes the superseded expiry index.                                            |
| 009     | `session_incarnation`                        | Adds session-incarnation identity.                                              |
| 010     | `session_idempotency_lifetime`               | Aligns idempotency records with session lifetime.                               |
| 011     | `tool_idempotency_session_index`             | Adds the session-scoped idempotency index.                                      |
| 012     | `outbox_session_index`                       | Adds the outbox session index.                                                  |
| 013     | `outbox_delivered_retention_index`           | Adds the delivered-outbox retention index.                                      |
| **014** | `guard_session_idempotency_lifetimes`        | **Requires generation-aware lease writers. Drain older writers first.**         |
| 015     | `terminal_session_retention_index`           | Adds the terminal-session retention index.                                      |
| 016     | `outbox_delivered_retention_order_index`     | Adds the ordered outbox-retention index.                                        |
| 017     | `drop_outbox_delivered_at_index`             | Removes the superseded delivered-at index.                                      |
| **018** | `require_idempotency_lease_context`          | **Requires transaction-local lease context. Drain intermediate writers first.** |
| 019     | `guard_idempotency_session_identity`         | Guards session identity on idempotency records.                                 |
| 021     | `restore_outbox_session_incarnation_trigger` | Restores the outbox incarnation trigger.                                        |

There is no `020_*.sql` file in the repository; migration 021 follows 019 in
the checked-in history. The migrator applies the files that exist and records
their actual version numbers. Do not create a placeholder migration or renumber
021 to fill that gap.

Migrations 014 and 018 are writer-compatibility boundaries:

1. Stop admitting new calls on writers that use the 1.2.0 lease contract. Let
   active calls finish and flush their durable writes. Stop runtime workers,
   recovery coordinators, reapers, and any direct store writers. Confirm no
   old writer can restart.
2. Run the ordered migration sequence while those writers remain stopped. This
   single maintenance window satisfies both drain points.
3. If migrations are applied in stages, drain writers that lack lease
   generation fields before 014. Before 018, also drain any intermediate
   writer that sends the row fence and generation but does not set the
   transaction-local lease context.
4. Start only 2.0.0-compatible writers after the migrations complete. Keep
   old workers stopped while legacy idempotency records or provider-side
   deduplication windows remain relevant.
5. Verify lease acquisition/renewal, recovery paging and acknowledgment, and
   tool claim/completion/quarantine against a staging copy before reopening
   production traffic.

Do not roll back the application to a writer that predates the 014 or 018
contract boundaries. Preserve a database backup and use a forward fix if a
post-migration issue occurs.

## Other 2.0.0 additions

- Managed sessions expose `complete()`, `stop()`, and `finalSession`. Transport
  half-close and remote hangup are reported separately, and
  `authorizeUpgrade` runs before the WebSocket upgrade.
- Web Client Audio buffers startup media and handles heartbeat/reconnect
  lifecycle. Twilio webhook handling includes replay protection.
- `onSessionTrace` is opt-in and metadata-only; it excludes audio, transcripts,
  tool arguments, and tool results.
- Sarvam Bulbul v4 Flash is available as a TTS provider option.
- Redis session transaction writes are batched with `MSET` operations of up to
  500 records. Redis Cluster remains unsupported by the related multi-key Lua
  scripts.

Run the repository release checks and the package's PostgreSQL/Redis
integration checks before upgrading production. Use the [release guide](../releasing.md)
for the protected-main, exact-artifact, and npm provenance requirements.
