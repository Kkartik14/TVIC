# Security policy

Please do not report security vulnerabilities through a public GitHub issue or
pull request. Public disclosure can put users at risk before a fix is ready.

## Report a vulnerability

Use GitHub's private vulnerability reporting flow:

[Report a vulnerability privately](https://github.com/Kkartik14/TVIC/security/advisories/new)

Include, when safe to share:

- the affected package and version;
- the impact and a concise threat model;
- reproduction steps or a minimal proof of concept;
- whether credentials, personal data, audio, or call metadata may be exposed;
- a suggested mitigation, if you have one.

Do not include real credentials, caller data, recordings, or production secrets.
Redact them from logs and proof-of-concept material.

## Security pull requests

Security fixes are the only exception to TVIC's issue-first contribution rule.
Do not open a direct public pull request before reporting the vulnerability.
After private coordination, a maintainer may ask for a focused pull request or
may prepare the fix directly. Keep the vulnerability details private until the
maintainer confirms that public disclosure is safe.

For the general contribution process, see
[CONTRIBUTING.md](./CONTRIBUTING.md).
